¿Qué es y para qué sirve?

El conector Palo Alto PAN-OS permite que el agente de Ruvic administre un firewall Palo Alto (o Panorama) mediante su API: consultar reglas de seguridad, agregar objetos de dirección y confirmar (commit) los cambios de configuración pendientes. Combina la REST API (JSON) para reglas y objetos con la XML API clásica para el commit, ya que PAN-OS no expone un endpoint REST equivalente.

Una vez configurado, puedes pedirle al agente cosas como:

  • "Lista las reglas de seguridad del vsys1 y dime cuáles permiten tráfico desde internet."
  • "Agrega un objeto de dirección para el servidor 10.0.0.5/32 y confírmalo."
  • "¿Qué reglas usan el objeto servidor-web?"

Operaciones soportadas:

Operación Qué hace
security.list_rules Lista las reglas de seguridad del vsys configurado (solo lectura)
security.add_object Agrega un objeto de dirección a la configuración candidata (no aplica cambios hasta el commit)
security.commit Confirma (commit) los cambios pendientes en la configuración activa del firewall
Este conector hace cambios reales A diferencia de un conector de solo lectura, add_object y commit modifican la configuración del firewall. Un commit aplica los cambios a la configuración activa y puede afectar tráfico real de producción. El conector no crea, modifica ni elimina reglas de seguridad — solo objetos de dirección y el commit de cambios ya presentes en la configuración candidata.

Prerrequisitos

  • Un firewall Palo Alto PAN-OS (o Panorama) accesible por HTTPS, con PAN-OS 10.1 o superior recomendado.
  • Acceso administrativo al firewall (Device → Admin Roles y Device → Administrators) para crear un rol y una cuenta dedicada, solo durante la configuración inicial.
  • Acceso de red desde la plataforma Ruvic hacia la interfaz de administración del firewall (puerto 443 alcanzable; regla de firewall si aplica).
  • La URL base del firewall o Panorama (ej. https://firewall.empresa.com) y, si aplica, el nombre del VSYS a administrar.

Configuración en el fabricante

Vas a crear un rol de administrador personalizado y una cuenta dedicada para Ruvic. No reutilices el administrador por defecto ni una cuenta con rol Superuser: una cuenta dedicada con permisos mínimos permite auditar la actividad del agente y limitar el impacto si la API Key se compromete.

  1. Crea el rol de administrador personalizado. Ve a Device → Admin Roles → Add. Crea un rol (por ejemplo ruvic_panos_role) de tipo XML API/REST API y ajusta los permisos exactamente así:
    • Read Only sobre Policies (necesario para list_rules).
    • Read-Write únicamente sobre Objects → Addresses (necesario para add_object). Deja el resto de "Objects" sin acceso o solo lectura.
    • Permiso de Commit habilitado (necesario para commit).
    • Sin acceso de escritura sobre Network, Device Setup ni ningún otro apartado. Nunca uses el rol Superuser.
    [ Captura: Device → Admin Roles con los permisos mínimos configurados — reemplazar por assets/img/panos-admin-role.png ]
  2. Crea la cuenta de administrador dedicada. Ve a Device → Administrators → Add, crea un usuario (por ejemplo ruvic_admin) con una contraseña fuerte (mínimo 16 caracteres, generada aleatoriamente) y asígnale el rol personalizado creado en el paso anterior como Administrator Type → Role Based.
  3. Genera la API Key con el endpoint keygen. Con la cuenta dedicada (no el admin por defecto), genera la API Key llamando al endpoint keygen de la XML API: 
    curl -k "https://firewall.empresa.com/api/?type=keygen&user=ruvic_admin&password=CAMBIA_ESTA_CONTRASEÑA"
    La respuesta incluye un elemento <key>: cópialo, lo usarás en el formulario de Ruvic (campo API Key). Guárdalo en un lugar seguro; no lo compartas ni lo pegues en canales sin cifrar.
  4. Verifica la cuenta y la API Key. Confirma que la API Key funciona y que el rol tiene los permisos esperados probando una llamada de solo lectura: 
    curl -k "https://firewall.empresa.com/api/?type=op&cmd=<show><system><info></info></system></show>&key=TU_API_KEY"
    Si responde con información del sistema (sin error de autenticación), el fabricante quedó listo. Anota la URL base, la API Key y el VSYS para la siguiente sección.

Permisos requeridos

Principio de mínimo privilegio: la cuenta de Ruvic solo necesita estos permisos. No otorgues el rol Superuser ni acceso de escritura sobre Policies, Network o Device Setup.

Permiso Para qué sirve
Policies — Read Only Consultar las reglas de seguridad (list_rules). No permite crear, modificar ni eliminar reglas.
Objects → Addresses — Read-Write Crear objetos de dirección en la configuración candidata (add_object). No se otorga escritura sobre otros tipos de objetos.
Commit Aplicar la configuración candidata a la configuración activa del firewall (commit).
Nunca otorgues Superuser El rol Superuser (o cualquier rol con acceso de escritura sobre Network o Device Setup) le daría a la API Key la capacidad de reconfigurar interfaces, rutas o el propio firewall — muy por encima de lo que el conector necesita. Si el rol tiene más permisos de los listados aquí, redúcelo antes de continuar.

Configuración en Ruvic

Entra a Settings → Conectores, busca la tarjeta Palo Alto PAN-OS y pulsa Configurar. Diligencia el formulario con los valores que obtuviste en la sección anterior:

Campo Descripción
base_url URL base del firewall o Panorama, incluyendo https:// (ej. https://firewall.empresa.com). Obligatorio.
api_key API Key generada en el paso 3 de la configuración en el fabricante, con la cuenta dedicada ruvic_admin. Se almacena cifrada. Obligatorio.
vsys VSYS a administrar. Opcional; por defecto vsys1. Cámbialo si tu firewall usa sistemas virtuales múltiples y quieres limitar el conector a uno específico.
verify_ssl Verificar el certificado TLS del firewall. Opcional; por defecto activado (true). Desactívalo únicamente en pruebas contra un firewall con certificado autofirmado en un entorno de laboratorio — nunca en producción, ya que deshabilita la validación del servidor y expone la conexión a ataques de intermediario.
connect_timeout Timeout de conexión en segundos. Opcional; por defecto 15.

Guarda el formulario. Ruvic ejecuta automáticamente una prueba de conexión (equivalente a un ping contra la API) y confirma si la configuración es válida.

Verificación

  1. Prueba de conexión automática. Al guardar la configuración, Ruvic consulta la información del sistema del firewall usando la API Key ingresada. Si la tarjeta del conector pasa a estado Configurado, la conexión y las credenciales son válidas.
  2. Prueba con el agente. Pídele al agente algo simple y de solo lectura, por ejemplo: "Lista las reglas de seguridad del firewall". Si el agente responde con la lista de reglas (nombre, acción, origen/destino), el conector funciona de extremo a extremo.
  3. Prueba opcional de escritura (con precaución). Solo si quieres validar el flujo completo: pide al agente crear un objeto de dirección de prueba y confírmale que confirme (commit) el cambio explícitamente. Recuerda que el commit afecta la configuración activa; hazlo en un firewall de laboratorio si es posible.
Qué esperar en cada operación list_rules es inmediato y de solo lectura. add_object modifica la configuración candidata sin efecto inmediato. commit puede tardar hasta 2 minutos: el conector sondea el estado del job cada 3 segundos y retorna el resultado final (OK o FAIL).

Solución de problemas

Problema Causa probable y solución
API Key inválida o permiso insuficiente (código 403 / 16) La API Key es incorrecta, expiró, o el rol de la cuenta no tiene los permisos mínimos (Policies Read Only, Objects → Addresses Read-Write, Commit). Regenera la API Key con keygen y revisa el rol en Device → Admin Roles.
Timeout de red / no se pudo alcanzar el firewall La plataforma Ruvic no puede llegar a la base_url por el puerto 443. Verifica reglas de firewall, que la interfaz de administración esté habilitada para HTTPS, y aumenta connect_timeout si la red es lenta.
El commit falla o retorna FAIL Puede haber un error de validación en la configuración candidata, otro commit en curso, o la cuenta no tiene permiso de Commit. Revisa el detalle del job en Task Manager del firewall y confirma el permiso de Commit del rol.
La tarjeta queda en "Sin configurar" después de guardar La prueba de conexión automática falló. Revisa que base_url incluya https://, que la API Key se haya copiado completa (sin espacios) y que verify_ssl coincida con el tipo de certificado del firewall (desactívalo solo si es autofirmado y estás en pruebas).
Respuesta XML inválida o inesperada de PAN-OS Suele indicar una versión de PAN-OS distinta a la esperada (REST API v10.1) o un proxy/balanceador modificando la respuesta. Verifica la versión de PAN-OS y que la base_url apunte directamente al firewall o Panorama, no a un proxy intermedio.

Preguntas frecuentes y notas de seguridad

¿Dónde se guarda la API Key?

La API Key se almacena cifrada en la plataforma Ruvic y nunca se muestra en texto plano después de guardarla, ni se registra en logs. El conector la lee únicamente desde la variable de entorno RUVIC_PANOS_API_KEY en tiempo de ejecución.

¿Con qué frecuencia debo rotar la API Key?

Se recomienda rotarla cada 90 días, o inmediatamente si sospechas que se expuso. Genera una nueva con keygen usando la cuenta ruvic_admin y actualízala en el formulario de configuración; la anterior deja de funcionar en cuanto la cuenta genera una nueva clave.

Sospecho que la API Key se comprometió, ¿qué hago?

Revoca el acceso deshabilitando o eliminando la cuenta ruvic_admin en Device → Administrators del firewall, genera una nueva cuenta y API Key, actualiza la configuración en Ruvic, y revisa el historial de commits y el log de auditoría del firewall en busca de cambios no reconocidos.

¿Por qué nunca se otorga el rol Superuser?

El conector solo necesita leer reglas, escribir objetos de dirección y confirmar cambios. El rol Superuser otorgaría control total del firewall (interfaces, rutas, VPNs, usuarios, etc.), muy por encima de lo necesario. Si la API Key se filtrara, un rol personalizado con permisos mínimos limita drásticamente el daño posible frente a una cuenta Superuser comprometida.

¿El conector puede crear o modificar reglas de seguridad?

No. El conector solo lee reglas de seguridad, crea objetos de dirección y confirma (commit) cambios ya presentes en la configuración candidata. No expone ninguna operación para crear, modificar o eliminar reglas.

add_object y commit hacen cambios reales A diferencia de una simple consulta, add_object modifica la configuración candidata del firewall y commit la aplica a la configuración activa, afectando tráfico real de producción. Confirma siempre con el equipo responsable antes de pedirle al agente que haga commit, especialmente en firewalls de producción.
